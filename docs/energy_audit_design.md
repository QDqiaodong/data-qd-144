# energy-audit 设计说明与取舍

## 职责切分

- `energy_audit.validate`：纯结构与值域校验，不碰仓库。布尔冒充整数、未知
  字段、重复 id、越界数值在此拒绝；空候选区间**不**在此拒绝（那是计量
  无解，不是格式错误）。
- `energy_audit.api`：仓库快照读取、归因权重、精确积分、联合枚举与报告
  组装；`audit(warehouse_path, source_data, source_sha256)` 是可测试 API。
- `energy_audit.cli`：路径冲突拒绝、严格 JSON 读取、原子发布、退出码 2。

## 关键取舍

### 1. 全联合枚举，而非边际推断

一套解释是完整 d 向量；预算约束把若干区间耦合成联合约束。若先逐工单求
边际上下界再取笛卡尔积，会把“各自可达但不可同时达”的组合误认为可行
（测试里有专门的反例：两工单能耗都是 `(d1+d2)/2`，一个要 0 一个要 100）。
因此实现直接枚举完整候选积：每区间候选至多 3 个（零/一/两次回绕），区间
总数 ≤ 10，故完整解释空间 ≤ 3^10 = 59049，枚举是确定且有界的。预算剪枝
（部分和 + 剩余区间可达范围，系数全非负所以端点即界）只删去不可能可行
的子树，不改变结果。每个候选对全部线性型的贡献向量预先算好，递归只做
分数加减。实测（Python 3.11，本仓库容器）：合同上限规模（10 区间 × 3
候选 = 59049 解释、8 工单 + idle + 合计共 20 个线性型）无预算约 2.7 秒；
验收与随机 oracle 用例均为毫秒级。测试中的 oracle 用 `itertools.product`
独立重枚举，逐实例比对计数、全部极值与平局见证。

### 2. 精确有理数，禁止先舍入

所有系数（时间占比、布局长度占比、电价）都是 `Fraction`；指标是 d 向量
的线性型，逐叶子精确求值。报告只输出最简分数 `{num,den}`（`den>0`），
没有任何浮点。代价是枚举内层是分数加法，比浮点慢，但规模有界（见上），
换取的是可复算的确定性。

### 3. 单只读事务快照

仓库以 `mode=ro` 打开（不存在则报错且不建库），`query_only`，显式
`BEGIN` 包住 revision 与全部 `plan_history` 读取。WAL 下读者看到事务开始
时的一致性快照，并发 finish 要么整体可见、要么整体不可见——历史布局、
完工身份与 revision 永远来自同一快照。布局只认 `plan_history.plan_json`：
started/open 快照与当前棒材库存都不是权重来源（余料回库再消耗后，原棒
的完工布局仍是唯一权重来源，测试覆盖）。

### 4. 见证与平局

枚举按规范序（meter_id UTF-8 字节序、区间开始时间）字典序生成候选，极值
只在严格更优时替换，因此每个极值留下的见证天然是字典序最小的达成向量。
不同指标的见证可以不同；报告不声称全部极值可同时达到，但每个见证都被
独立复算约束：满足全部预算、逐解释工单+idle 等于全表积分。

### 5. 守恒作为不变量

每基本时间片（读数×run×电价交点）的能耗/费用被恰好分给一个 run 或该表
idle，run 内权重和为 1，因此 `Σ工单 + Σidle = Σd`（费用同理）对每条解释
逐条成立。该恒等式在测试中对每个极值见证独立复算。

### 6. 复用而非新造

严格 JSON（重复键/非有限数拒绝）、ident 规则、原子符号链接拒绝发布、
`<code>: <message>` + 退出码 2 全部复用 `cutting_stock.common` 与现有 CLI
模式；`cutting-stock`、`stock-*`、`ap-*` 契约零改动。

## 明确不做

- 不规划、不改库存、不过账、不配对采购；不写任何业务表。
- 不输出冲突核（infeasible 时只给计数 0 与空范围）。
- 不建模跨表守恒、功率曲线形态或测量噪声；区间内功率恒为 `d/dt`。
