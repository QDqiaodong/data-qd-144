# 离线有限库存切割计划仓 — 设计与资源记录

## 1. 模块与职责

| 模块 | 职责 |
| --- | --- |
| `common.py` | 共享严格 JSON（拒绝重复键、`NaN`/`Infinity`）、`ident` 标识校验、原子报告发布（临时文件 + `os.replace`，拒绝符号链接）。原 FFD 单次契约保持不变。 |
| `stock_planner.py` | **精确**全局优化器。`best_packing` 求固定零件集的最优装箱；`plan_open_orders` 枚举全部工单子集并按合同字典序选全局最优；`deferral_reasons` 给出延期原因。 |
| `stock_store.py` | SQLite schema 与事务边界。所有事实表、计划快照、幂等日志、余料/损耗历史在单个 `BEGIN IMMEDIATE` 事务内提交。 |
| `stock_api.py` | 严格校验、操作编排（收料/工单/修订/撤回/start/finish）、幂等与 revision 控制、报告组装、提交前不变量检查。 |
| `stock_cli.py` | `stock-init` / `stock-apply` / `stock-report` 三个子命令；仅用 Python 标准库。 |
| `cli.py` / `packing.py` / `model.py` | 原有单次 FFD 契约，未改动。 |

## 2. 精确搜索策略与剪枝（不以 FFD 替代最优性）

`best_packing` 是逐件深度优先的**分支定界**，FFD/BFD 仅用于产生初始 incumbent（上界），绝不用于决定最终解：

1. 零件按“长度降序、UTF-8 字节 id”固定顺序放置，**不展开零件排列**；每件要么放入已开的兼容棒，要么开一根未使用的兼容棒。
2. **incumbent 收紧**：BFD 给出初始最少棒数上界；每找到更优完整解即在位收紧，后续分支按该棒数剪枝。
3. **乐观下界**（只可能偏小、永不误剪）：
   - 容量下界：剩余件总长减去已开棒余量后，按最大棒容量估算还需的新棒数，忽略锯缝（分棒只会减少锯缝）；
   - 等级阈值下界：对每个等级 `g`，需求等级 `>=g` 的剩余件只能用等级 `>=g` 的棒，按其最大容量估算不可避免的新棒数；
   - 总容量可行性：剩余需求超过当前全部空闲容量则立即剪枝。
4. **同形棒对称剪枝**：已开棒按（已耗长度、件数、等级）去重；新开棒按（棒长、等级）去重，等价分配只探索一次。
5. **规范状态备忘录**：键为（剩余件位掩码、占用棒形状多集、未用棒形状多集），合并等价回访；B 平局元组仍在叶节点用具体棒 id 精确比较。
6. 目标在固定零件集上为 `(消耗棒数, 消耗棒长度和, B 元组)`；长度和等价于最小化总余料（零件总长与锯缝对该零件集恒定）。外层 `plan_open_orders` 再按 `(priority 总和, 接受单数, 棒数, 长度和, A 元组, B 元组)` 在全部 2^8 工单子集上取字典序最小。

正确性由 `tests/test_stock_planner.py` 的**独立穷举**守护：它用最朴素的全枚举（所有工单子集 × 所有可行零件-棒分配，无任何剪枝）在 200+ 随机小实例上逐项比对接受集合、棒数、长度和与 B 元组。

## 3. 事务、快照边界与失败恢复

- 每个 `stock-apply` 批次在一个 `BEGIN IMMEDIATE` 事务内完成：校验 → 事实变更 → 重规划/冻结 → 写快照与幂等日志 → `_enforce_invariants` → revision +1 → `COMMIT`。任何异常都 `ROLLBACK`，事实、分配、余料、revision 与幂等日志保持原子一致（由回滚测试验证）。
- revision 是单源整数（`meta` 表），成功才 +1；失败批次不改任何事实。
- `batches` 表以规范化请求字节的 SHA-256 记录幂等结果：同 `batch_id` 同载荷返回首次响应；同 `batch_id` 异载荷报 `IdempotentConflict`；`expected_revision` 不符报 `RevisionError`。
- `start` 在一个事务内冻结当前 revision 的全部已接受工单及其棒（棒置 `occupied`、工单 `started`、零件 `cut`、写 active 快照），并对剩余未开工工单基于**仅未占用棒**重算 open 快照。最多一个 active 计划。
- started 期间可收料/更正未开工工单，但只能使用未占用棒；占用棒 id 不可被收料复用。`finish` 原子释放分配棒（置 `consumed`），达 `reuse_min` 的余料以稳定新 id 入库（`rem-<plan>-<seq>`）并继承原棒等级，不足记 `waste`；随后立即对全部仍开放工单（含此前延期者）重规划。
- 计划余料仅在 open 快照中标记 `planned_reusable`，**不入库、不可被任何规划使用**；只有 finish 提交的合格余料才成为可用棒。

## 4. 资源记录（限定规模，可复现）

复现：`PYTHONPATH=src python3 tests/perf_stock_planner.py`（Python 3.11，仅标准库；`RUN_SLOW_PERF=1` 额外运行人造最坏例与满规模联合规划）。

一次代表性运行（随机种子固定为 `20261116`）：

| 规模（件/棒） | 样本 | 最大耗时 | 中位耗时 | tracemalloc 峰值 |
| --- | --- | --- | --- | --- |
| 6/4 | 8 | ~6 ms | ~1 ms | ~23 KiB |
| 10/7 | 6 | ~180 ms | ~60 ms | ~0.6 MiB |
| 14/10 | 3 | ~0.9 s | ~75 ms | ~3.3 MiB |
| 18/12（合同上限） | 3 | ~14 s | ~10 s | ~49 MiB |
| 联合规划 5 工单/8 棒 | 1 | ~2.2 s | — | ~6.5 MiB |

说明：切割装箱是 NP 难问题。绝大多数实例在亚秒级完成；当大量小零件落在近均匀、等级区分的棒上时，分支定界需证明不存在更优棒数，最坏实例耗时达数秒至十几秒、峰值约 50 MiB。硬上限（12 棒、18 件、8 工单）使状态空间有界且内存可控；优化器始终返回被穷举测试验证的全局最优解，不以 FFD 启发式冒充最优。

## 5. 报告确定性

报告内所有列表按 UTF-8 字节序稳定排序；JSON 以 `sort_keys=True`、`ensure_ascii=False`、`allow_nan=False` 输出，同状态字节一致。报告经 `common.save` 原子发布，失败不破坏旧报告。
